How it works

The encryption is between people, not between servers.

Pheme uses MLS, the IETF standard for group messaging. Keys are made and rotated on the devices themselves. The server sees who is in a conversation and when, and nothing of what was said.

Pick your server

Pheme asks which server you are signing in to, the way an email client does. Point it at the one you belong to.

Your devices hold the keys

Every device is its own member of the group with its own keys. Adding or removing one rotates the group's keys, so a device that leaves cannot read what comes after it.

The server forwards ciphertext

It stores messages so they arrive when you come back online, and it cannot open them. Losing the server does not expose your history. Losing your last device is what the recovery code is for.

Servers can federate

Someone on one server can write to someone on another, and the encryption still runs between the two people rather than between the two machines. Federation works off a signed list of hosts, so it is not open to anyone who turns up.

What you get

Encrypted, including the parts most apps leave out.

Chats and groups

Direct and group conversations, encrypted end to end, on as many devices as you want to use.

Voice calls

Call setup is encrypted with the same keys as your messages, rather than going over a separate channel the server can watch.

Photos and files

Attachments are encrypted like anything else. The server stores files it cannot open.

Your history moves with you

A new device gets the conversation history from one you already use. A recovery code keeps a sealed copy off the device, so losing a phone does not cost you what was said.

In your language

The whole app is translated: chat lists, settings, security warnings, the recovery code screen. English and Russian today, and the strings live in the repository, so a new language is a pull request.

iPhone, Android and the browser

The same account on all of them, each device with its own keys. The web client runs the same MLS implementation as the phones, compiled to WebAssembly, so none of them is the weaker one. Screenshots below are from the mobile app.

Channels

A notification feed with an HTTP endpoint.

Build finished, order shipped, sensor tripped, rehearsal moved. Anything that can make an HTTP request can post to a channel, and everyone subscribed gets a push notification and a history they can scroll back through.

In practice people point deploy logs at it, and doorbells, and the cron jobs that until now had nowhere to report.

# post to a channel from anything that speaks HTTP curl -X POST https://your-server/v1/channels/$ID/posts \ -H "Authorization: Bearer $TRIGGER_TOKEN" \ -H "Content-Type: application/json" \ -d '{"body":"Deploy v1.4.0 finished in 3m12s"}'

Run your own

The whole stack is a Docker Compose file.

API, web client, database, push and TURN. Point the app at your host and it is your messenger. There is no account with us to create, and nothing that depends on this site staying up.

Pheme is free software under the GPLv3. Claims about encryption that nobody can check are just marketing, so the code is there to be read.

# bring up a server git clone https://github.com/rh1tech/pheme.git cd pheme/deploy cp .env.example .env # set your domain docker compose up -d

FAQ

Common questions.

Can the server read my messages?

No. Content is encrypted on your device and decrypted on the recipients' devices, and the keys never leave them. The server keeps the ciphertext and the routing details it needs to deliver it: who is in a conversation, when a message was sent, how big it was.

What happens if I lose my phone?

Another device you are still signed in on can pass the history to a replacement. With no other device, your recovery code opens a sealed copy that was stored off the device under that code. The app shows the code once and asks you to write it down, because a code we could recover for you would be a code we could use.

Is it really open source?

Yes. Client, server and the MLS integration, under the GNU General Public License v3. You can read it, change it, and run your own version.

Do I have to run a server?

You need a server to sign in to. It can be your company's, your community's, or one you set up yourself in an afternoon.

What does it collect?

An email address for sign-in, the display name you pick, an avatar if you upload one, and a push token so notifications can reach you. No ads, no trackers, no third-party analytics, no crash reporter. The privacy policy lists all of it.
