How it works

The encryption is between people, not between servers.

Pheme uses MLS, the IETF standard for group messaging. Keys are derived and rotated on the devices themselves; the server sees who is in a conversation and when, and nothing of what was said.

Pick your server

Pheme asks which server you are signing in to, the same way an email client asks. Point it at the instance you belong to.

Your devices hold the keys

Every device is its own member of the group with its own key material. Adding or removing one rotates the group's keys, so a device that leaves cannot read what comes next.

The server forwards ciphertext

It stores messages so they arrive when you are offline, and it can never open them. Losing the server does not expose your history; losing your last device is what a recovery code is for.

Servers can federate

Someone on one instance can message someone on another, and the encryption still runs end to end between the people. Federation is permissioned by a signed list of hosts rather than open to anyone who shows up.

What you get

Everything encrypted, including the parts most apps leave out.

Chats and groups

Direct and group conversations, encrypted end to end, on as many devices as you like.

Voice calls

The signalling is encrypted under the same keys as your messages, not a separate channel the server can watch.

Photos and files

Attachments are encrypted like everything else. The server stores blobs it cannot open.

Your history follows you

A new device is handed the conversation history by one you already trust, and a recovery code seals a copy off-device — so losing a phone does not mean losing what was said.

Channels

A notification feed with an HTTP endpoint.

Build finished, order shipped, sensor tripped, rehearsal moved — anything that can make an HTTP request can post to a channel. Every subscriber gets a push notification and a permanent history they can scroll back through.

It is the part people end up using for things they never expected: a deploy log the whole team can read on a phone, a doorbell, a cron job that finally has somewhere to speak.

# post to a channel from anything that speaks HTTP curl -X POST https://your-server/v1/channels/$ID/posts \ -H "Authorization: Bearer $TRIGGER_TOKEN" \ -H "Content-Type: application/json" \ -d '{"body":"Deploy v1.4.0 finished — 3m12s"}'

Run your own

The whole stack is a Docker Compose file.

API, web client, database, push and TURN. Point the app at your host and it is your messenger — no account with us, no dependency on this site staying up.

Pheme is open source. If something here matters to you, you can read exactly how it works rather than take our word for it.

# bring up a server git clone https://github.com/rh1tech/pheme.git cd pheme/deploy cp .env.example .env # set your domain docker compose up -d

Questions

The ones worth asking.

Can the server read my messages?

No. Message content is encrypted on your device and decrypted on the recipients' devices; the keys never leave them. The server holds ciphertext plus the routing metadata it needs to deliver it — who is in a conversation, when a message was sent, how large it was.

What happens if I lose my phone?

Another device you are still signed in on can hand the history to a replacement. If you have no other device, a recovery code opens a copy of your history that was sealed off-device under that code — which is why the app asks you to write it down once, and why nobody but you can use it.

Is it really open source?

Yes — client, server and the MLS integration. Encryption claims that cannot be checked are marketing, so the point of publishing it is that you do not have to believe this page.

Do I have to run a server?

No. Sign in to one that already exists — your company's, your community's, or a friend's. Running your own is an option, not a requirement.

What does it collect?

An email address for sign-in, the display name you choose, an avatar if you upload one, and a push token so notifications can reach you. No ads, no trackers, no third-party analytics, no crash reporter. The privacy policy lists it in full.
